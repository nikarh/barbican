barbican

barbican reads your servers’ logs, decides with rules which addresses are abusing your services, and blocks them in the kernel, on the server and on your router.

It is one program with one configuration file and a web UI. Countries and public blocklists can be blocked as a whole, people who log in are never locked out, and every ban says which rule made it and what the address did.

Quick startRead the docsSource on GitHub

Linux with nftables; OpenWrt and iptables routers. MIT or Apache-2.0. Written in Rust.

Why barbican

  • Everything in one place. Bans from logs, country blocking and blocklists usually take three tools and a dashboard. Here they share one set of rules, one allow list and one UI.
  • Blocks where traffic arrives. If your server sits behind a proxy or a router’s port forward, a ban on the server alone may not stop anything. Edge agents apply the same blocks on the router.
  • Small enough for a router. Lists are merged into ranges before they reach the kernel, the edge agent uses 6 to 10 MB, and it writes to flash only when it stops.
  • Hard to turn against you. The UI has no network port of its own, edges trust only your agent’s certificate, and logins make an address trusted.

Compared with fail2ban, CrowdSec and others

What it is made of

Each part has an interface of its own, and these are the implementations that exist today.

Log inputs
A container’s log through the Docker API, a file followed across rotation, the systemd journal, or a VictoriaLogs query for logs shipped from other machines.
Parsers
Traefik access logs, OpenSSH, Authelia, and a regular expression for anything else. Any parser works with any input.
Rules
Match paths, methods, statuses, hosts, user agents, user names and lists, and ban once a threshold is reached within a time window. The defaults catch exploit probes, scanners and password guessing.
Lists
Countries and continents from a geolocation database, and feeds such as Spamhaus DROP, FireHOL level 1, blocklist.de, Tor exits, or Cloudflare’s ranges to allow.
Firewalls
nftables on the server and on OpenWrt; iptables with ipset on router firmware without nftables. Blocks are kernel sets with timeouts, so they hold while barbican is stopped.
Packages
Debian and Arch packages and static binaries for x86_64 and aarch64; OpenWrt packages with LuCI pages for armv7, aarch64 and x86_64; the UI as a container image.

How the pieces fit

 server logs ─► agent: parse ─► rules ─► bans, trust ─► SQLite
 (local, or shipped        │
  from other servers)      ├─► kernel firewall on this server
                           └─► TLS ─► edge agents ─► kernel firewall on routers

One agent holds the rules, the lists and the history, and blocks on its own server. Logs from other servers can be shipped to it. Edge agents on routers connect to it and block what it blocks, so an address banned for probing one service can’t reach any of them. The UI talks to the agent through a local socket, and reaches browsers only through your authenticating reverse proxy.

On a phone

The UI is served by a small container next to your reverse proxy, behind its login. It works under a path prefix, and its layout follows the screen: on a phone the panels stack, the grids keep the columns that matter, and the tabs move to the bottom.

Install

Static binaries and packages for x86_64 and aarch64, edge agents for OpenWrt and for routers without nftables. Release files are signed. Details are in Install.

  • Debian / Ubuntu
  • Arch Linux
  • OpenWrt

Then say where the logs are, and start it in dry run first: [firewall] enabled = false decides and records everything, and blocks nothing.

Features

  • The nftables table and its sets, reconciled with what should be blocked
  • The edge protocol: a journal of changes for edges, and their mirror of it
  • Parsers for Traefik, sshd and Authelia logs, and for any log with a regular expression
  • Rules, the ban policy and geolocation, with defaults for common attacks
  • Storage, blocklists and the rule set, with parsers that borrow from the line instead of allocating
  • The engine: records what rules matched, trusts addresses people log in from, and bans on thresholds
  • Run the agent: log sources, the firewall, the edge API and the UI's RPC, with a systemd unit
  • Barbican-edge: applies the agents' blocks on an OpenWrt router
  • LuCI pages for barbican-edge: its status, and its settings in UCI
  • The web UI: overview, addresses and what they did, events, bans, rules, lengths, countries, lists and blocklists
  • Ban lengths per network (ASN) and per blocklist, for addresses many people share; an iCloud Private Relay preset
  • Barbican-edge-ipset: the edge agent with iptables and ipset, for routers without nftables (Asuswrt-Merlin)
  • The edge API over TLS only, with the agent's certificate pinned by the edges
  • The UI's API on a unix socket, and barbican ui-proxy to serve the UI from a container
  • Barbican import, for the history of logs
  • Events of routed requests say which route they went to
  • The UI proxy says why the agent can't be reached
  • The UI shows that it can't reach the agent, and why
  • The settings' lists are edited in place, one way for all of them
  • The settings say how much blocking countries and continents takes
  • Barbican-vlogs, a VictoriaLogs query's history as timestamped lines
  • An address's activity and bans in sortable grids, a page at a time
  • Show which geolocation databases are in use, how old, and when they update
  • Blocklists show their list's age, the last check, the next fetch and why one fails
  • Nftables set elements over netlink, reconciled only when something changed
  • web: Grids show every column on phones, and scroll sideways to them
  • web: An address's page leaves the phone's screen to its grid
  • IPv6 can be left out of the firewall (firewall.ipv6, the edge's ipv6)
  • edge: Dry_run follows the agents and saves their state, but leaves the firewall alone
  • edge: Agents push to edges over one persistent binary connection
  • web: An Edges view, and every edge's drops beside this host's
  • Feeds that allow what they list (never banned, let through first, here and on the edges), and Cloudflare's ranges as presets
  • edge: State saved compactly and only on a clean stop; edges without IPv6 get none
  • nft: The list sets hold merged address ranges instead of prefixes
  • e2e: Vm.sh forwards a port of this machine into a VM
  • The UI only on the agent's unix socket, checked by its peers' credentials; ui-proxy answers only a trusted proxy
  • Signed pacman and apt repositories (releases, and the builds of main), as portcullis has
  • Drop totals survive restarts and reboots, this host's and each edge's, kept by the agent

Performance

  • Barbican import streams its files, merged by time
  • Events list from an index in its order, overview sums from the index alone
  • edge: The ipset backend writes only changes and checks only its jump every minute
  • nft: Tell drift by the ruleset's generation, checked every minute, instead of notifications
