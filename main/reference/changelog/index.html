Changelog

Every release, newest first. Each version links to its GitHub release, which has the files and the authors of each change. This page is generated from CHANGELOG.md, which git-cliff writes from the commits when a release is made.

0.1.02026-11-11

Features

  • The nftables table and its sets, reconciled with what should be blocked
  • The edge protocol: a journal of changes for edges, and their mirror of it
  • Parsers for Traefik, sshd and Authelia logs, and for any log with a regular expression
  • Rules, the ban policy and geolocation, with defaults for common attacks
  • Storage, blocklists and the rule set, with parsers that borrow from the line instead of allocating
  • The engine: records what rules matched, trusts addresses people log in from, and bans on thresholds
  • Run the agent: log sources, the firewall, the edge API and the UI's RPC, with a systemd unit
  • Barbican-edge: applies the agents' blocks on an OpenWrt router
  • LuCI pages for barbican-edge: its status, and its settings in UCI
  • The web UI: overview, addresses and what they did, events, bans, rules, lengths, countries, lists and blocklists
  • Ban lengths per network (ASN) and per blocklist, for addresses many people share; an iCloud Private Relay preset
  • Barbican-edge-ipset: the edge agent with iptables and ipset, for routers without nftables (Asuswrt-Merlin)
  • The edge API over TLS only, with the agent's certificate pinned by the edges
  • The UI's API on a unix socket, and barbican ui-proxy to serve the UI from a container
  • Barbican import, for the history of logs
  • Events of routed requests say which route they went to
  • The UI proxy says why the agent can't be reached
  • The UI shows that it can't reach the agent, and why
  • The settings' lists are edited in place, one way for all of them
  • The settings say how much blocking countries and continents takes
  • Barbican-vlogs, a VictoriaLogs query's history as timestamped lines
  • An address's activity and bans in sortable grids, a page at a time
  • Show which geolocation databases are in use, how old, and when they update
  • Blocklists show their list's age, the last check, the next fetch and why one fails
  • Nftables set elements over netlink, reconciled only when something changed
  • web: Grids show every column on phones, and scroll sideways to them
  • web: An address's page leaves the phone's screen to its grid
  • IPv6 can be left out of the firewall (firewall.ipv6, the edge's ipv6)
  • edge: Dry_run follows the agents and saves their state, but leaves the firewall alone
  • edge: Agents push to edges over one persistent binary connection
  • web: An Edges view, and every edge's drops beside this host's
  • Feeds that allow what they list (never banned, let through first, here and on the edges), and Cloudflare's ranges as presets
  • edge: State saved compactly and only on a clean stop; edges without IPv6 get none
  • nft: The list sets hold merged address ranges instead of prefixes
  • e2e: Vm.sh forwards a port of this machine into a VM
  • The UI only on the agent's unix socket, checked by its peers' credentials; ui-proxy answers only a trusted proxy
  • Signed pacman and apt repositories (releases, and the builds of main), as portcullis has
  • Drop totals survive restarts and reboots, this host's and each edge's, kept by the agent

Fixes

  • Save the edge agent's state when a save comes due, and when it is stopped
  • Index events by what, so pruning doesn't hold the database for hours
  • UI calls made while not connected wait for the connection
  • Save where each source got to as the agent stops
  • Grids fill the page down to its bottom
  • Grids are dark in the dark scheme
  • Grids show that they load, that nothing matches, or why they failed
  • Country pickers offer only countries of today
  • The block picker shows continents with their code and a globe, as their rows do
  • The image's first healthchecks run every second
  • web: The browser tab names the screen or the address, and Barbican capitalized
  • web: Grids keep their layout from the first paint to the rows
  • web: Switching screens shows their grids' rows in the first frame
  • web: The phone's tab bar no longer jumps in Firefox for Android
  • web: Less above the grids on a phone
  • web: Rule and blocklist cards give their text the full width
  • web: Inputs take the full width on a phone
  • web: Time columns are as wide as their longest text, measured in the grid's font
  • packaging: The Arch package's scripts run, and an upgrade restarts the agent
  • web: No pinned column on a phone, where the address alone took most of the width
  • web: Compact columns on a phone, measured from their content, and the address filter's labels in full
  • web: Event times show the hour they were counted in, as a range
  • web: Geolocation and blocklists are panels of their own, each with a Details link like the others
  • web: Panel links (Details, All bans) as small and quiet as the panel's title
  • openwrt: An upgrade of the .apk restarts barbican-edge (apk runs post-upgrade, not post-install)
  • luci: The status page says when it may not read the status (log in again) instead of that the agent isn't running
  • luci: The status page may read the status file where /var/run really is (rpcd checks the resolved path, /tmp/run)
  • luci: The status page says when the edge runs dry, and the settings have dry run and IPv6
  • edge: Its count of listed prefixes leaves IPv6 out when it doesn't load IPv6, as the agent's does
  • traefik: A client written as a forwarded chain (visitor, proxy) is parsed, and the last hop is blamed
  • nft: Setup keeps a chain whose rules are already right, and with it what their counters counted

Performance

  • Barbican import streams its files, merged by time
  • Events list from an index in its order, overview sums from the index alone
  • edge: The ipset backend writes only changes and checks only its jump every minute
  • nft: Tell drift by the ruleset's generation, checked every minute, instead of notifications
